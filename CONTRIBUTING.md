# Contributing

Thank you for improving the skill. Contributions should make technical communication more useful without narrowing it to a single platform, customer type, company, or personal biography.

Русская версия: [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md).

## Before opening a pull request

1. Search for an existing issue or pull request.
2. Keep the change focused on one improvement.
3. Preserve the skill's language-neutral scope and do not add unverified claims or mandatory phrasing based on one anecdote.
4. Update both Russian and English guidance when the rule applies to both languages; explain intentional language-specific differences in the pull request.
5. Run the repository validation workflow locally when possible.

## Pull request expectations

- Explain the user-facing writing problem and the proposed rule or example.
- Include a short before/after example when it clarifies the change.
- Do not submit private client material, credentials, internal links, or personal data.
- Keep examples generic and technically plausible.
- Use English for repository-facing metadata and code comments; use the paired Russian files for Russian-language guidance.

## Review and merge policy

`main` is maintained through pull requests. The repository owner reviews changes before merge. Do not push directly to `main`, force-push the default branch, or merge a pull request that has unresolved review feedback.

## Reporting issues

Use the issue forms for a reproducible problem or a clearly scoped improvement. A good report states the requested writing context, expected behavior, observed behavior, language, and any relevant constraints.
