# Русские форматы

Используйте эти формы как основу, а не как шаблон для механического копирования. Оставляйте только то, что нужно адресату.

## Предложение или ответ клиенту

1. Приветствие, если оно уместно для канала.
2. Одно предложение с понятным результатом.
3. Компактный план выполнения в двух-пяти предложениях.
4. Одно важное условие, риск или способ проверки.
5. Минимальный конкретный следующий шаг.

```text
Здравствуйте!

Переведу сервис на новый API без изменения текущего пользовательского сценария. Сначала сопоставлю текущие endpoint, добавлю слой совместимости там, где он нужен, и проверю критические сценарии на staging перед выкатом.

Для точной оценки нужны текущий API-контракт и доступ к staging с правами, близкими к production. Пришлите их, пожалуйста, и я подтвержу объём и сроки.
```

## Статус

Добавляйте `Статус`, `Влияние`, `Следующий шаг` и `Риск` только тогда, когда каждый пункт несёт информацию.

```text
Статус: миграция завершена на staging, smoke-тест прошёл.
Влияние: production-трафик не изменялся.
Следующий шаг: подготовить production-выкат после подтверждения.
Риск: откат ещё не проверялся на production-данных.
```

## Техническое решение

Сначала назовите рекомендацию, затем причину, компромисс и действие. Не перечисляйте варианты без необходимости, если можно дать рекомендацию.

## Редактирование документации

Описывайте стабильное поведение системы, предусловия, входы, выходы, ограничения и ошибки. Не описывайте процесс написания текста и не ссылайтесь на переписку.
